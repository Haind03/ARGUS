# YARA & Sigma authoring

> **Scope:** defensive detection content for the user's own machine. Rules describe artefacts; they
> never contain working payloads.

## Workflow
1. **Source the signal**, rare, stable artefacts from `malware-triage` / `process-memory-analysis`
   (mutex, PDB path, config keys, unusual imports) beat generic strings.
2. **Draft** from templates: [yara-template.md](references/yara-template.md), [sigma-template.md](references/sigma-template.md).
3. **Encode AV-safe**: [av-safe-rules.md](references/av-safe-rules.md), hex or `\xNN`-escaped regex for
   tool/malware strings; starter set is generated by `tools/build_yara.py`.
4. **Validate**: `python -I skills/yara-sigma-authoring/scripts/validate_rules.py`
5. **Test**, positive: the sample/dump (`yara -s rule.yar sample`); negative: a clean folder
   (`yara -r rule.yar C:\Windows\System32` should be silent, run on your own PC only).
6. **Ship**, YARA into `skills/references/yara/` (used by triage, memory vadyarascan, process-memory),
   Sigma into `skills/references/sigma/`, Python heuristics into `engine/argus/rules.py` + a pytest case.

## New ARGUS heuristic checklist
`@rule(id, tactic, technique, title, action)` · yields `Candidate(artifact, key, signals)` · stable `key`
(normalised, no PIDs/GUIDs) · mitigating signals for known-benign · FP notes in the tactic reference ·
`tests/test_rules.py` positive + negative case · add the technique to `tools/techdata.py` and re-run `python -I tools/gen_tactic_skills.py`.
